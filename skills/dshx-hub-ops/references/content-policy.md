# Catalog content policy

Write English and Chinese as independent, natural catalog content grounded in the same verified source set. Preserve package names, versions, dependency ranges, commands, identities, URLs, licenses, and compatibility statements exactly.

## Facts and editorial copy

- Describe only capabilities supported by a manifest, patch, maintained documentation, or other authoritative evidence.
- Mark uncertainty by omitting the claim, not by turning it into confident marketing language.
- Do not use Stars, downloads, rankings, temporary trends, or repository activity as stable feature claims.
- Do not infer framework compatibility from similar dependencies or package names.
- Summarize what the plugin enables, the environment it affects, and meaningful constraints; avoid generic praise and duplicated repository copy.

## Localizations and SEO

Both locales must contain a useful name, concise summary, overview, concrete highlights, SEO title, and SEO description that meet the live contract. Translate meaning, not syntax. Installation notes are optional and should exist only when verified setup differs from the displayed install target.

Both localizations reference the exact `contentSourceHash` computed from hashed editorial sources. If any used source changes during writing, discard the stale result and rebuild from the new evidence. User reviews and replies are never translated into catalog or SEO content.
